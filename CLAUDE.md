# CLAUDE.md

Portfolio site: Next.js App Router, TypeScript, static export (`output: "export"`), React Three Fiber + GLSL for the
contour field, Motion (and Motion+) for springs and gestures, React `<ViewTransition>` for route morphs. npm only.

## Commands

- `npm run dev` — dev server plus the local endpoint the dev-only tuning panel saves through
- `npm run build` — builds `out/` for `SITE_MODE` (`construction`, `basecamp`, `live`; default `live`)
- `npm run preview` — serve `out/` like a static host (honours `NEXT_PUBLIC_BASE_PATH`)
- `npm run lint` · `npm run typecheck` · `npm test` · `npm run check:contrast` · `npm run check:content` · `npm run report:size`
- `npm run check:figures` — case-study numbers agree with their data file; committed images are current
- `npm run images` — render and encode the case-study artefact images (Playwright + sharp)
- `npm run test:e2e` · `npm run check:legibility` · `npm run report:transfer` — Chromium checks against `out/`
- `npm run terrain` — regenerate `public/terrain` from swisstopo data (downloads ~100 MB once into a git-ignored cache)

Installing needs `MOTION_TOKEN` in the environment (see README). Never write the token into a file.

## Structure

- `src/app` — routes (`/`, `/work/[slug]`, `/about`), root layout, global CSS
- `src/components` — `terrain/` (contour field), `card/` (Summit Card, deck), `case-study/` (template blocks),
  `transition/`, `hud/`, `about/`
- `src/content` — all copy and card data (`cards.ts`, `case-studies.ts`, `site.ts`, `about.ts`); components never
  hardcode copy. `examples/` holds flagged fictional examples (`example: true`): only in basecamp and preview
  builds, never in live ones (`includesExamples` in `src/hosting/config.ts`).
  Unfilled facts are `[PLACEHOLDERS]` (or `href: null`); stats are optional and render only with a value.
  `check:content` lists placeholders; `npm run build` checks them per `SITE_MODE` (see README).
- `src/lib/case-study.ts` — the case-study content model (waypoints, blocks, figures)
- `src/styles/tokens.ts` — design tokens
- `src/config` — committed tuning values written by the dev panel
- `src/hosting` — Netlify hosting: domains (`config.ts`), the Basecamp gate, the under-construction page
- `scripts/` — Node scripts only (must run on Windows, macOS and Linux)
- `public/terrain` — generated by `npm run terrain`, committed
- `artefacts/` — one HTML/SVG source per case-study image plus a shared stylesheet; `npm run images` writes
  `public/media/<slug>/` and the manifest next to the data file (both committed; PNG masters are not)

## Rules

- Branches: `basecamp` is the integration branch and pull requests target it; `main` is production.
- Tokens are the single source of truth: colours, type, durations, easings and springs come from
  `src/styles/tokens.ts` (exposed to CSS as custom properties). Don't hardcode values that exist as tokens.
- Every runtime asset URL that doesn't go through `next/link` or `next/image` (textures, terrain SVGs, fetch calls)
  must use `asset()` from `src/lib/asset.ts`, or it breaks in a sub-path build.
- Accessibility: semantic HTML first, content readable without JavaScript, keyboard operable, WCAG AA contrast
  (on the sheet colour only sheet-ink, moss-ink, alpenglow-ink or ground).
- Motion: every effect needs a reduced-motion twin (`prefers-reduced-motion` or the in-site Calm map toggle,
  exposed as `html[data-motion="reduced"]` and `useReducedMotion()`).
- Keep heavy code out of the initial bundle (Three/R3F and Motion load lazily) and keep transfer per visit small.
- Case studies: waypoint headings state the finding; at most one key insight and one pull quote per page. A case
  study with a data file writes every number as a `{{token}}` (`src/lib/fill.ts`), in copy and artefacts alike;
  after changing data or an artefact, run `npm run images` (check:figures fails on stale images).
- Next.js docs for the installed version live in `node_modules/next/dist/docs/`.
