# Locales: German and English

One session (the only one running) makes the site bilingual, German and English, with a language
switcher, without changing the design or the motion. Contract: `docs/contracts.md#locales-l1l11`
(L1–L11).

## Branch

`claude/exciting-pascal-64dips`, merged into `main` once verification passed; `main` pushed and
deployed once.

## Plan

1. Content per locale: the English modules move to `content/en/`, `content/de/` gets the same
   shape in German; the cards' language-free data (ids, order, identities, paths) moves to
   `content/deck.ts`. The schema stays one schema; the build-time checks run for both locales.
2. Routes under `src/app/[locale]/`, both locales generated; every internal link and every path
   decision (which card, home, About) made without the locale.
3. The root and the 404 page outside the locales, written after the build (one inline script, no
   framework).
4. The switcher in the header; the switch as a client navigation with its own transition type.
5. The German translation, then overflow checks at 390, 1024 and 1440 px.
6. Smoke (both locales, full tier), screenshots, docs, merge, deploy.

## What shipped

**Routing and detection (L1–L4)**

- `src/app/layout.tsx` is the root: `<html>`, the pre-paint script, the background field and
  `RouterBridge` (play / return navigation and the back / forward replay). It never remounts.
  `src/app/[locale]/layout.tsx` holds the chrome and remounts when the language changes. The
  first version put `<html>` in the `[locale]` layout: a switch then remounted the whole document
  body, React re-acquired `<html>` and wiped what the pre-paint script had written (calm tier,
  field colour, renderer), and the WebGL field restarted. Hence the split.
- `<html lang>`: the root layout cannot read the locale, so `scripts/i18n-pages.mjs` writes
  `lang` into each page's HTML after the build (16 pages) and `LocaleSync` keeps it in step on the
  client. Per page: canonical, hreflang `de`, `en`, `x-default` (the root); per locale: title
  template, description, `og:locale` (`de_CH`, alternate `en_GB`).
- Root (`dist/index.html`): `pickLocaleScript` (`src/lib/i18n.ts`) inline in `<head>`, then
  `location.replace(<base><locale>/ + search + hash)`. Order: stored choice (localStorage
  `locale`), the first `navigator.languages` entry starting with "de" or "en", English if there
  are languages but none match, German if there are none. `<noscript>` links to both.
- 404 (`dist/404.html`): the same rule. An address from before the locales (`/random/about/`,
  `/random/work/…`, `/random/logo-lab/?c=…`: earlier links and bookmarks) moves to the same page in
  the picked language when it exists (a HEAD request first). Otherwise it fetches `/<locale>/404/`
  (the localized 404 page) and writes it into the document, so the unknown address stays. Without JavaScript or if the fetch
  fails: the 404 sentence and a link home, in both languages. Next's own fallback 404
  (`dist/404/`, `dist/_not-found/`) is removed.
- Server components read the page's locale with `getContent()` (`src/lib/content.ts`); every
  `[locale]` layout and page calls `setRequestLocale(params.locale)` first
  (`src/lib/request-locale.ts`, React `cache`). `next/root-params` would read it without that, but
  only when the locale segment holds the root layout (see above).

**Switcher (L6–L9)**

- `nav[data-locale-switcher]` between About and the calm switch: "DE · EN". Each a real link to
  the same page in that language (`hreflang`, `lang`, visible code plus the language's name for
  screen readers); the active one `aria-current="page"` with the drawn `.link` underline, like the
  current page link. 44 × 44 px targets, the dot between them takes no room.
- Click: stores the choice, finishes running reveals, remembers the section under the header and
  how far into it, navigates with type `locale` and `scroll={false}`. The `[locale]` layout
  remounts; `LocaleSync` (a layout effect before `Reveals`) restores the reading position, puts
  focus back on the switcher and announces the new title once the transition is over.
- One cross-fade over `--dur-s` (calm × 0.6, reduced 160 ms linear): the page and the card faces
  via `locale-fade` in the React maps (`LOCALE` entries), the header, hand, rail and footer via
  `:root[data-locale-switch]`. No group moves; the field stays live. Never a card morph.
- The reveal system runs the remounted page as kind `locale` (on screen: final at once; below:
  on scroll); the table store moves nothing when only the language changes; the breaker lift is
  kept; the rare pull does not roll. The home intro never replays (`table-drawn` is already set,
  and a click or key press skips a running intro).
- Browser back / forward across languages replays as the same `locale` cross-fade (no stored
  choice). Found by testing: when the history listener lived in the hand, Next's own popstate
  handler remounted the hand first and removed the listener mid-dispatch; it now lives in the root
  (`RouterBridge`), registered before Next's.
- On the 404 page the other language's link reloads the address; the 404 page then shows the
  stored language. Its `href` is that language's 404 page (the server knows only the 404 route).

**Content (L5)**

- `content/de`, `content/en`: each a `Content`: `site.ts`, `hand.ts` (slim), `cases/*.ts`,
  `pages/*.ts`, `illustrations.ts` (titles, descriptions and labels of every drawing, which were
  English defaults inside the components), `index.ts`; `content/de/images.ts` (German alt text,
  also used for the photo credits). `content/deck.ts` holds the cards without text.
- D7: client components no longer import content modules. The `[locale]` layout passes the
  active locale's slim chrome (site labels, the hand, the Coffee card) to `ChromeProvider`
  (`src/lib/chrome.tsx`): `useChrome()` in React, `activeChrome()` in the hand eggs. Language-free
  lookups (`cardIdForPath`, `identityOf`) for the table store, play and the field.
- Build-time checks (`src/lib/content.ts`): every count for both locales; the same slugs and card
  order in both; the count line per locale ("13 Projekte · 2014–2025"); German strings without
  "ß", em-dash or semicolon. `scripts/images/check.mjs` checks counts and alt text per locale.
- New labels: `site.header.nav` ("Website" / "Site", formerly hard-coded), `site.header.language`
  ("Sprache" / "Language"), `site.settings.calmLabel` (visible) next to `settings.calm`
  (accessible name): "Ruhig" / "Ruhigere Animationen", and in English "Calm" / "Calm motion"
  (see Known issues). The week ring's ritual labels and days moved from the Management page into
  `illustrations.WeekRing`.
- German body text hyphenates (`:lang(de)`, `type.css`: `.t-body`, `.t-lead`, decision-card
  fields, margin notes, timeline stops, project rows); headings, display type and labels never.
- The logo lab exists under both locales and stays English (`lang="en"` on its root): a tool,
  not content.

**Translation notes**

- Swiss Standard German throughout: "ss" (schliessen, ausserdem, Strassenverkehrsamt),
  Swiss terms where natural: Entscheid, innert, Traktandenliste, Lancierung, Detailhandel,
  Sitzung, Lernende, Service public, Höhenkurven (the swisstopo term, also in the lead).
- Informal "du" wherever the reader is addressed (contact, Coffee card, 404, workshop methods,
  hiring); principles and how-I-work items as infinitives ("Sagen, was man anders machen würde.").
- Kept as they are: proper and product names (Allmend, Lindengrund Informatik, Hyper Island,
  swissALTI3D, One Piece TCG, Magic: The Gathering, Yu-Gi-Oh!, V60, WCAG 2.1 AA, Angular, React,
  Vue), method names (1-2-4-All, Crazy 8s, How Might We, Lightning Decision Jam, Dot voting,
  Brainwriting 6-3-5, Rose, Thorn, Bud, Troika Consulting, Pre-mortem, Empathy map, Fishbowl,
  Impromptu Networking, Crazy Eights, Dot Voting, Design Studio), the engagement models
  (Check-up, Sprint, Embedded) and role titles (UX Team Lead, Senior UX Designer, Product Owner).
- Terms decided: "Design System" in two words (the display title "Design System Allmend": a
  single "Designsystem" is too wide for the title at 390 and 1024 px, and title words cannot
  break); card "Führung" with the hero "Wie ich führe"; "Teamaufbau" as the first card's type;
  "Anlaufstelle" for the front door; "Einsatzmodelle"; "Karrieremodell"; "Critique" and
  "Research-Share" kept as ritual names; "Umziehende" for the resident lane; FTE kept.
- Numbers: decimal comma (4,5 / 5, 3,1 → 4,4, 4,0 FTE), "%" without a space (scoreboard values
  wrap between words, a space would split "71 %"), CHF 2000, 1200.
- Fitted to the layout: the two scoreboard values with "weeks" became "9 → 3" with "Wochen
  Wartezeit auf Design, im Schnitt", and "21 → 4" with "Tage von der Idee zum klickbaren
  Prototyp" ("Wochen" is wider than a scoreboard column from 1024 px); short decision titles
  ("Ein Kern für alle Frameworks", "Beraten statt prüfen", "Feste Modelle statt Tickets", "Die
  Stufen mit dem Team schreiben") and hiring steps ("Erstes Gespräch", "Gespräch zum Portfolio",
  "Mittag mit dem Team").
- Gender-fair where it stays short: neutral forms ("Personen im Design", "Projektleitende",
  "Teilnehmende", "Lernende"); generic forms where a neutral one would be clumsy (job levels such
  as "Erfahrener Designer").
- Fixed strings used word for word: "Bern, Schweiz · UX Team Lead", "Was ich mitbringe",
  "(eine Auswahl meiner Projekte)", "Zieh eine Karte", "Zurück", "Über mich", "Ruhig" /
  "Ruhigere Animationen", "Kaffee?", "Zurück zum Tisch", "Höhenkurven abgeleitet aus
  swissALTI3D. Quelle: Bundesamt für Landestopografie swisstopo".

## Known issues

- Initial JS 170.2 KB gzip, 0.2 KB over the advisory budget (169.2 KB before).

- The smoke check "home first visit (full): name, label, lines, divider, items, hand, chrome"
  fails on desktop in most runs, in both languages. It is not new: the untouched build passes it
  in 2 of 10 runs here (this build 2–3 of 10, the same spread), and the first-visit animation
  schedule is identical (logged animation starts within 15 ms). By the H4 tokens the last "What I
  bring" item and the first card start about 10 ms apart, and the check compares when each crosses
  a visibility threshold. Left as it is (backlog: home intro timings).
- The English calm switch shows "Calm" (accessible name "Calm motion"), mirroring the German
  "Ruhig" / "Ruhigere Animationen": with the new switcher, "Calm motion" pushed the header 4 px
  into the right margin at 390 px.
- `next dev` has no page at `/` (the root is written after the build): open `/de/` or `/en/`.
- The 404 page's language links (for middle-click and no-JavaScript visitors) point to the other
  language's 404 page; a normal click reloads the unknown address in that language.
- Browsers without view transitions switch without the cross-fade (as every other transition).
  Lighthouse, axe and cross-browser runs were not part of this round.
